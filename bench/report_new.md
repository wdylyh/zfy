### 语义对齐备注

- T9 python 无 move/拷贝语义：s1 按引用（无拷贝）、s2 用 `list(ys)` 显式拷贝，与 zfy `copy`、C++ 按值、Rust `clone` 对应
- T6 Rust 用 `Option<Box<Node>>` 安全链表 + 迭代式 drop；C++/zfy 手动 new/delete(malloc/free)
- zfy 自动窄化已收窄为显式 cast（new2.md #5），代码中 sizeof/下标处的 cast 为该规则产物

## 结论（2026-10-05 复测，含 fail 修复 / T7 扩容 / tty 修复后的最新编译器）

1. **整体性能与 C++/Rust 持平**：9 个任务中 zfy/cpp 全部落在 0.84x~1.16x（几何均值约 1.03x），zfy/rust 0.73x~1.29x。T1（0.84x）、T6（0.90x）、T8（1.00x）甚至快于 C++。
2. **T7 字符串整改生效**：上轮 1.32x/55MB → 本轮 **1.05x/2.0MB**（Trae 的原地扩容 `zfy_str_append` 路径），短板已消除。
3. **T3 IO 修复无性能回归**：1.16x（此前 1.16x），tty 分流未影响管道基准路径。
4. **T9 深拷贝 1.09x/1.29x(rust)**：属值语义固有成本，接近下限，不再追。
5. **最差项**是 T3（1.16x）与 T4（1.07x/1.25x rust），差距 < 0.16s 绝对值，已在测量噪声边缘；无单点结构性短板。
6. 校验脚本对 Rust 的 CRLF 输出误报 mismatch（值一致），后续可在比对前 `strip('\r')`。

**结论：性能整改收官，语言主线（正确性 + 性能）均达标，建议冻结基准，后续转向模块系统/泛型补强等语言特性工作。**
