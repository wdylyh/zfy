## 新任务说明（T6-T9）

| 任务 | 内容 | 考察点 |
|---|---|---|
| T6 | 100k 节点链表：malloc/new/Box 逐节点建链、遍历求和、逐个释放 | struct + 指针 + 堆分配 |
| T7 | 3000 token 字符串拼接、split、find、长度统计 | 字符串操作（值语义拷贝） |
| T8 | 泛型 struct Box<T> + 泛型函数 pick，450k 次构造/比较 | 泛型单态化 + struct 构造 |
| T9 | 1M 元素列表：move 免克隆求和 + 30 次深拷贝求和 | 所有权 move vs 值语义拷贝 |

### 语义对齐备注

- T9 python 无 move/拷贝语义：s1 按引用（无拷贝）、s2 用 `list(ys)` 显式拷贝，与 zfy `copy`、C++ 按值、Rust `clone` 对应
- T6 Rust 用 `Option<Box<Node>>` 安全链表 + 迭代式 drop；C++/zfy 手动 new/delete(malloc/free)
- zfy 自动窄化已收窄为显式 cast（new2.md #5），代码中 sizeof/下标处的 cast 为该规则产物

## 结论

1. **总体：zfy 与 C++/Rust 已基本持平（T1-T6、T8 在 0.90x~1.09x 区间）**，旧任务 T1-T5 相比上一轮报告（1.15~1.25x）进一步收敛，ref/自动 move 落地后读路径免克隆是主要贡献。
2. **T7 字符串任务是当前最大短板（1.32x / 1.34x，内存 55MB vs 1.5MB）**：`s = s + ...` 逐次拼接时 zfy 的中间串分配/拷贝开销显著高于 C++/Rust 的可扩容 string。整改方向：给 `+=`/拼接走 rope 或预分配扩容路径（记入后续优化）。
3. **T9 值语义深拷贝路径 1.09x~1.12x**：30 次深拷贝中 zfy 的逐元素克隆略慢于 memcpy 风格的 C++ 拷贝构造；move 路径本身已无开销。这是语义成本，接近合理下限。
4. **内存全面占优**：除 T7 外，zfy 内存与 C++/Rust 同级（Python 为其 8~40 倍）。
5. T8 证明**泛型单态化零运行时开销**：450k 次泛型构造与 C++/Rust 完全同级（0.94x~0.98x）。

复测方式：`python bench/newbench.py`（约 40s，输出 results_new.csv 与本报告）。
