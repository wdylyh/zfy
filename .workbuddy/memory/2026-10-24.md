
## UI bug 修复轮（用户报 main.zfy UI 演示四问题）
注意：本轮开始时发现工作区 main.zfy 已被 IDE 改写为 247 行 markdown 渲染器、
grammar.md 被覆盖为 zfy 源码（367 行）——grammar.md 已从 git 恢复，main.zfy
保持用户工作区版本未动（collab w-052 提醒用户确认）。

修复（runtime.c + widgets.zfy）：
1. **元素消失/点击无反应**：根因 = 事件队列洪流丢事件——快速移动鼠标时
   MOVE 填满 256 环形队列，"队列满丢新事件"把夹在其中的 DOWN/UP/KEY 丢掉
   （press 边沿检不出 → 组件不响应；状态 dirty 不置 → "消失"，再点几下
   重新触发重绘"又显示"）。修：①入队前 MOVE 合并（队尾未消费 MOVE 直接
   覆盖坐标）；②队列满时非 MOVE 事件挤掉队头 MOVE 腾位。
2. **选中判断不灵敏**：防御性修复——InputBox.draw 与 pos_from_mx 开头
   gui_font(16,0)，保证宽度测量/绘制/命中三处同字号（防上游字号状态污染
   导致点击定位错位）。逻辑级 pos_from_mx 边界测试过。
3. **全选覆盖残留**：逻辑验证 del_selection + Ctrl+A（KEY_CTRL+65） +
   多字节（"你好"6 字节）选区覆盖均正确（新增 widgets_test 1b 断言组）；
   用户观察到的"残留"最可能是事件丢失导致选区/按键时序错乱（同根因 1）。
4. **placeholder**：InputBox.ph 字段 + UI.placeholder(s) 标签 +
   app.set_placeholder(k,s)；draw 空文本时 C_SUB 灰字画提示（不可选中、
   不进 text_out）；focus 时空框也画光标+下划线。
另：Label.draw 清背景宽度取 max(bg_w, 当前文本宽, last_w 记忆值)——文本
变短不再残留旧字符（残影修复）。
- 测试：examples/widgets_test.zfy 新增 1b 组（全选覆盖/多字节/placeholder/
  pos_from_mx 边界）全过；ui3_test PASS；全量回归 failures: 0。
- grammar.md §18.0a：placeholder 标签 + set_placeholder 文档。
- 验证截图被用户前台游戏画面占据，未做视觉级确认（逻辑级已全覆盖）。

## TextArea/InputBox 鼠标拖选（用户报 §18.2/§18.3 缺口），commit 1852e29
- InputBox 原本已有拖选（on_press/on_drag/on_release 已接线）；本次补全 TextArea：
  锚点 sax/say + sel_on 激活标志 + dragging；on_press 记锚、on_drag 扩选并置
  sel_on、on_release 收尾；App step/on_hover 接线（texts 点击走 on_press，
  非按下帧 on_release，按住左键 on_drag 跟随）。
- sel_on 设计要点：仅真实拖选置位，collapse 一律清零——业务直改 cx 不会产生
  "幽灵选区"（回归中 textarea_test 直改 cx 的旧用例验证了这一点）。
- collapse 必须在光标移动之后调用（放分支开头则移动后锚点又落后，下一键误判
  有选区——曾致 widgets_test 连环 FAIL）。
- 顺带修既有 bug：insert_at_cursor 的 cx 公式 `length(segs[ns-1]) - length(suffix(ln, cx))`
  漏了光标偏移（行中粘贴光标落错位），改为 `cut + length(segs[ns-1]) - length(suffix(ln, cut))`。
- grammar §18.2/§18.3 补拖选与选区联动文档；widgets_test 1c 断言组；回归 failures: 0。
- 坑：bash heredoc 传 `\n` 到 python 会被工具层吞反斜杠，字符串含 \n 的替换
  一律用行级 python（readlines + 行内 replace）。
